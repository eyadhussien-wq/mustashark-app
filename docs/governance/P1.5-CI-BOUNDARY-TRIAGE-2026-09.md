## Decision

`S01-03 Join concurrency` is classified as **LEGACY / REGULATED-DEPENDENT TEST EVIDENCE** for the current Lawyer OS v1 construction track. It is **not a Neutral Core acceptance gate**.

The test is quarantined rather than repaired for the current construction scope.

## Evidence

The test directly provisions `bookings` rows with `payment_status = 'paid'` and `escrow_status = 'held'`, and exercises `/api/bookings/join` against the existing booking state machine. The current booking controller also contains payment/escrow/commission gates in the same domain surface. This makes the existing S01-03 Join test unsuitable as a clean Neutral Core gate without reintroducing the legacy booking model into the Lawyer OS v1 acceptance path.

The active test also validates concurrent lawyer/client joins, duplicate joins, idempotency, appointment-window guards, and authorization. These are valid historical engineering concerns, but their current fixture and route contract are coupled to the legacy booking/financial domain.

## Non-decision

This triage does **not** declare the underlying `recordJoin` product behavior permanently obsolete. A future Client Portal / consultation-session track may define a new Neutral Core contract and a fresh test against that contract, without inheriting the legacy financial fixture.

## Acceptance rule

The current construction branch may proceed only when its active CI gates validate the actual Neutral Core scope. A green result caused merely by deleting a failing test is not sufficient by itself; the remaining CI set must pass and the next scope-specific tests must be added before Lawyer OS v1 is considered verified.
