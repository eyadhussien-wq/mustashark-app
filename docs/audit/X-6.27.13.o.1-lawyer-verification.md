# X/6.27.13.o.1 — Lawyer Authentication & Verification Boundary

Status: Audit hardening proposal

## Security rule

A self-declared `role=lawyer` is never proof of professional status.

New lawyer registrations must be persisted as:

`Pending → Admin Verification → Approved → Active`

No JWT/session is issued with effective lawyer privileges while the account is pending.

## Required invariants

- Client registration may activate only as `client`.
- Lawyer registration creates a `lawyer` identity with `accountStatus=pending`.
- Pending lawyers cannot authenticate into the lawyer workspace.
- Pending lawyers cannot receive service permissions merely because they supplied lawyer profile fields.
- Admin verification is the only route to `approved/active` lawyer status.
- Existing active lawyers retain normal authentication behavior.
- Portal-role mismatch remains denied.
- Membership in an office is separate from professional verification.
- Office membership cannot itself promote a user to verified lawyer status.
- Every verification, rejection, suspension, and activation must be auditable.
- Rejected/pending identities are never silently promoted by login.

## Audit test matrix

1. New local registration with `role=lawyer` → `pending`, no lawyer JWT.
2. New social registration with `role=lawyer` → `pending`, no lawyer JWT.
3. Pending lawyer login → denied with verification-pending state.
4. Client registration → client-only activation.
5. Existing lawyer login from client portal → role mismatch denied.
6. Existing client login from lawyer portal → role mismatch denied.
7. Office membership request for an unverified person → cannot grant lawyer authority.
8. Admin approval → account becomes active only through explicit verification action.
9. Admin rejection → account remains unable to use lawyer authority.
10. Repeated login while pending → state remains pending and no privilege escalation.

## No jumping rule

Do not proceed to X/6.27.13.o.2 until these invariants are implemented and verified by typecheck, tests, and an explicit audit pass.
