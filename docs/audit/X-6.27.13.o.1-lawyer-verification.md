# X/6.27.13.o.1 — Lawyer Authentication & Verification Boundary

Status: Audit hardening proposal

A self-declared `role=lawyer` is never proof of professional status.

New lawyer registrations must follow:

`Pending → Admin Verification → Approved → Active`

No pending lawyer receives an authenticated lawyer session or lawyer permissions.

## Audit invariants

- New lawyer registration persists as `accountStatus=pending`.
- Pending lawyer login is denied without issuing a privileged JWT.
- Office membership is separate from professional verification.
- Office membership cannot promote an unverified user to verified lawyer status.
- Existing active lawyers retain normal login behavior.
- Portal-role mismatch remains denied.
- Approval/rejection/suspension/activation must be auditable.
- Repeated pending login cannot escalate privileges.

## Gate

Do not advance to X/6.27.13.o.2 until the implementation passes typecheck, tests, and the explicit authentication audit matrix.
