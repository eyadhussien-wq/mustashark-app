## 2. Conclusive Finding — Neutral → Financial Schema Transitive Reachability

A repository-wide source-level transitive dependency violation is now positively established through branch-pinned source evidence.

The Neutral services import the public `@workspace/db/schema` entry point. The DB package declares that entry point as `./src/schema/index.ts`. The schema barrel then re-exports both Neutral schemas and Financial schemas from the same public surface.

Evidence chain:

`Neutral service → @workspace/db/schema → lib/db/src/schema/index.ts → Financial schema modules`

### 2.1 Neutral import edge

`neutralDocumentAuthorization.ts` imports multiple tables from `@workspace/db/schema`; `neutralAudit.ts` does the same. The Neutral matter/ownership services also consume the same public schema surface.

Branch-pinned source evidence: `neutralDocumentAuthorization.ts`, `neutralAudit.ts`, `neutralMatters.ts`, `lawyerClientOwnership.ts`.

### 2.2 Resolution edge

`lib/db/package.json` exposes:

- `.` → `./src/index.ts`
- `./schema` → `./src/schema/index.ts`

Therefore `@workspace/db/schema` resolves to the schema barrel rather than to a Neutral-only schema entry point.

### 2.3 Export/barrel edge

`lib/db/src/schema/index.ts` re-exports Financial modules including, among others:

- `./platformDues`
- `./representationFinance`
- `./paymentProofs`
- `./lawyerProposals`
- `./representationQuoteRequests`

The same barrel also exports the Neutral modules.

This makes the Financial schema modules transitively reachable from any Neutral module importing `@workspace/db/schema`.

### 2.4 Financial nature of the reachable modules

`platformDues.ts` contains platform commission authority and financial amount/status fields, including `PLATFORM_COMMISSION_RATE`, gross amount, commission rate, commission amount, and collection status.

`representationFinance.ts` contains representation quotes, milestones, escrow accounts, escrow transactions, commission tiers, lawyer wallets, wallet transactions, and related financial state.

These are therefore not merely generic database utilities; they are identifiable Financial authority/schema surfaces.

## 3. Security Interpretation

This is **not** a claim that Neutral authorization currently reads or mutates financial state. The inspected Neutral functions do not select or use those Financial tables for their authorization decisions.

The conclusive finding is narrower and architectural:

> The current public schema barrel creates a real transitive Neutral → Financial dependency/reachability path.

Therefore the previous statement "no Neutral → Financial transitive reachability established" is superseded by positive evidence of such reachability.

This invalidates any attempt to mark the Neutral dependency boundary GREEN while the shared barrel remains the resolution path for Neutral services.
