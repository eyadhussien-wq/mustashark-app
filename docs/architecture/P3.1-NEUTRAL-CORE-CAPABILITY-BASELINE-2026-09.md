# P3.1 — Neutral Core Capability Baseline

**Status:** APPROVED ARCHITECTURAL BASELINE / IMPLEMENTATION SEQUENCING PRESERVED  
**Branch:** `construction/lawyer-os-v1-p1-audit-2026-09`  
**Date:** 2026-09

## 1. Decision

Legal Calendar & Deadline Tracking, Matter-scoped Secure Messaging, and Neutral Time Tracking are classified as **P3 Neutral Core capabilities**.

They are not P4/P5/P6-only features because each can exist as lawyer operational data without requiring payment collection, marketplace behavior, custody, settlement, commission, or client-fund handling.

This baseline does **not** authorize implementation of all three immediately. P3.1-D remains the active document boundary gate and its CI evidence must be established before Document Authorization/Service implementation proceeds.

## 2. Target Neutral Core

The Neutral Core capability chain is:

`Identity → Lawyer Workspace → Lawyer↔Client Relationship → Matter → Documents / Calendar & Deadlines / Tasks / Secure Messaging / Time Tracking / Notifications / Audit → Export`

The following remain outside this authority:

`Marketplace / Commission / Client Funds / Escrow / Wallet / Settlement / Payout / Platform Dues / Financial Ledger / Payment Collection`

## 3. Legal Calendar & Deadline Tracking

### Classification

**P3 Neutral Core.**

### Minimum target model

`Matter → Legal Event / Deadline → Reminder → Audit`

Initial event categories may include:

- hearing
- filing deadline
- appeal/deadline
- expert session
- client appointment
- internal task
- reminder

### Security boundary

- Events are scoped to the owning lawyer and authorized matter/client relationship.
- `matterId` is not authorization by itself.
- Cross-lawyer and cross-matter access must be denied.
- Archive/revoke semantics must stop access without destructive deletion.

### Explicit non-goal

No Court Rules Engine or jurisdiction-specific deadline calculator is authorized here. Such behavior requires authoritative legal sources and specialist validation.

## 4. Matter-scoped Secure Messaging

### Classification

**P3 Neutral Core.**

### Minimum target model

`Active Relationship → Matter → Secure Conversation → Messages → optional authorized attachments → Audit`

### Security boundary

- Conversation access requires authenticated identity plus resource-level scope.
- A lawyer may access only authorized matters.
- A client may access only explicitly shared matter/conversation resources.
- Archived/revoked relationships must stop new access according to policy while retaining historical records.
- Message content and sensitive payloads must not be placed into ordinary audit metadata.

### Explicit non-goal

No client portal UI is required for this architectural baseline; Client Portal remains P5.

## 5. Neutral Time Tracking

### Classification

**P3 Neutral Core.**

### Minimum target model

`Matter → Time Entry`

Potential neutral fields:

- entry date
- duration
- activity/category
- description
- billable-preparation flag if later approved

### Financial boundary

Time tracking is operational data only.

It must not create or depend on:

- invoices
- payment collection
- lawyer fee calculation by platform
- commission
- wallet
- settlement
- payout
- escrow
- client-fund custody

Any future billing integration belongs to P4 and requires separate commercial/legal validation.

## 9. Security Invariants

1. Authentication does not imply resource authorization.
2. Relationship membership does not imply access to every resource.
3. Resource identifiers are never authorization credentials.
4. Server-side actor identity is authoritative.
5. Cross-tenant access is denied.
6. Revocation/archival stops access without deleting historical records.
7. Audit events are generated server-side for sensitive operations.
8. Neutral Core remains independent of financial and marketplace authorities.
