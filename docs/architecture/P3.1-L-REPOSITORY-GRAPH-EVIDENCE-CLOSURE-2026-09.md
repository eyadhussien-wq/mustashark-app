## 3. Confirmed Boundary Violation

The shared DB schema package exposes a combined public surface: `@workspace/db` exports `./schema` to `./src/schema/index.ts`. The schema barrel exports Neutral modules together with Financial/Marketplace modules. Therefore Neutral consumers using `@workspace/db/schema` can resolve the combined barrel and transitively reach Financial schema modules.

**Decision: PROVEN VIOLATION.**

## 4. Financial/Marketplace Surface

Branch-pinned evidence confirms authority-bearing Financial/Marketplace state in `platformDues`, `representationFinance`, `lawyerProposals`, `representationQuoteRequests`, and `paymentProofs`. `representationFinance` contains quotes, milestones, escrow accounts/transactions, commission tiers, lawyer wallets and wallet transactions.

The coupling chain is also proven:

```text
agreements
  → representationFinance

legalRepresentationDocuments
  → agreements
  → representationFinance
```

Thus `agreements` and downstream legal-representation documents cannot be classified as Neutral-only surfaces.

**Decision: PROVEN VIOLATION for the current combined public export contract.**

## 6. Cycles

## 7. Runtime Reachability

The API server's runtime entrypoint imports the route registry, and the route registry imports Financial/Marketplace route modules including proposal, agreement, milestone funding/allocation/proof/release/refund paths. Branch-pinned evidence therefore establishes that Financial execution code is part of the server's static runtime graph.

The Financial services inspected resolve Financial schema through `@workspace/db/schema` and perform authoritative financial mutations inside transactions. No direct Neutral authorization service import was established from the inspected Financial execution paths.

However, complete repository-wide runtime non-interference — including every dynamic loader, generated output, conditional export, externalized module, and runtime-resolved path — is not proven.

**Decision:**
- Financial runtime reachability: **PROVEN**.
- Financial → Neutral runtime non-interference: **FAIL-CLOSED**.
